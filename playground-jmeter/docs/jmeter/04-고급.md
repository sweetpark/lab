# JMeter 고급 - Assertion, 변수, CSV 데이터셋, 플러그인

## 1. Assertion (응답 검증)

Assertion은 응답이 올바른지 자동으로 검증하는 컴포넌트입니다.
단순히 "요청이 성공했다"를 넘어 "응답 내용이 정확한가"를 검사합니다.

### 1-1. Response Assertion (가장 기본)

HTTP 상태코드 또는 응답 바디에 특정 텍스트가 있는지 검사합니다.

```
HTTP Request 우클릭 → Add → Assertions → Response Assertion

설정:
  Field to Test: Response Code
  Pattern Matching Rules: Equals
  Patterns to Test: 200
```

**실무 사용 예시:**

```
POST /api/products
  → Response Code = 201 검사

GET /api/products/1
  → Response Body contains "테스트상품" 검사

PUT /api/products/1/stock/optimistic (재고 없을 때)
  → Response Code = 409 검사
```

### 1-2. JSON Assertion (API 응답 검증)

JSON 응답에서 특정 필드값을 검사합니다. **REST API 테스트에서 필수**입니다.

```
HTTP Request 우클릭 → Add → Assertions → JSON Assertion

설정 예시 (상품 조회 후 stock이 양수인지 검증):
  JSON Path: $.stock
  Additionally assert value: 체크
  Expected Value: [0-9]+  (숫자인지 확인)
  Match as regular expression: 체크
```

### 1-3. Duration Assertion (응답시간 제한)

응답시간이 지정값을 초과하면 에러로 처리합니다.

```
HTTP Request 우클릭 → Add → Assertions → Duration Assertion

Duration in milliseconds: 500
→ 500ms 초과 응답을 Error로 카운트
```

> **주의**: Duration Assertion은 Error %를 높이므로, 정확한 기준치를 알 때만 사용합니다. 성능 목표를 자동 검증하는 용도로 유용합니다.

## 2. 변수 (Variables) 활용

### 2-1. 사용자 정의 변수 (User Defined Variables)

테스트 전체에서 재사용할 변수를 정의합니다. 환경별로 값만 바꿔서 테스트할 때 유용합니다.

```
Test Plan 우클릭 → Add → Config Element → User Defined Variables

Name         Value
────────────────────
HOST         localhost
PORT         8090
BASE_URL     /api/products
```

HTTP Request에서 사용:
```
Server Name: ${HOST}
Port: ${PORT}
Path: ${BASE_URL}
```

### 2-2. 정규식 추출기 (Regular Expression Extractor)

응답에서 값을 추출하여 다음 요청에서 사용합니다. **상관관계(Correlation)**라고 합니다.

```
상황: POST /api/products 응답에서 생성된 id를 추출 → GET /api/products/{id}에서 사용

POST 응답 예시:
{"id": 42, "name": "테스트상품", "price": 10000, "stock": 100}
```

설정:
```
HTTP Request (POST) 우클릭 → Add → Post Processors → Regular Expression Extractor

Name of created variable: productId
Regular Expression: "id"\s*:\s*(\d+)
Template: $1$
Match No.: 1  (첫 번째 매칭)
Default Value: NOT_FOUND
```

이후 HTTP Request에서:
```
Path: /api/products/${productId}
```

### 2-3. JSON 추출기 (JSON Extractor)

JSON 응답에서 JSONPath로 값을 추출합니다. 정규식보다 직관적입니다.

```
HTTP Request (POST) 우클릭 → Add → Post Processors → JSON Extractor

Names of created variables: productId
JSON Path expressions: $.id
Match No.: 1
Default Values: ERROR
```

## 3. CSV 데이터셋 (CSV Data Set Config)

실제 다양한 데이터로 테스트할 때 CSV 파일에서 데이터를 읽어옵니다.

### 사용 시나리오

```
나쁜 방법: 모든 요청이 id=1 상품만 테스트
  → 캐시 히트율이 100%가 되어 실제와 다름

좋은 방법: 1~1000번 상품을 골고루 테스트
  → 실제 운영과 유사한 캐시 히트율/DB 접근 패턴
```

### 설정 방법

1. `test-data/products.csv` 파일 생성:
```csv
productId,productName,price
1,상품A,10000
2,상품B,20000
3,상품C,30000
```

2. Thread Group 우클릭 → **Add → Config Element → CSV Data Set Config**

```
Filename: test-data/products.csv
Variable Names: productId,productName,price
Delimiter: ,
Recycle on EOF: true   ← 데이터 소진 시 처음부터 반복
Stop thread on EOF: false
Sharing mode: All threads  ← 모든 스레드가 순서대로 나눠 씀
```

3. HTTP Request에서 사용:
```
Path: /api/products/${productId}
Body: {"name":"${productName}","price":${price},"stock":100}
```

## 4. 타이머 (Timer)

실제 사용자는 요청 사이에 생각하는 시간(Think Time)이 있습니다. 타이머로 시뮬레이션합니다.

### Constant Timer

모든 요청 사이에 고정 대기 시간 삽입

```
Thread Group 또는 HTTP Request 우클릭 → Add → Timer → Constant Timer
Thread Delay: 1000  (1초 대기)
```

### Gaussian Random Timer

평균과 표준편차 기반의 랜덤 대기 시간 (더 현실적)

```
Deviation: 500   (표준편차 500ms)
Constant Delay Offset: 1000  (최소 1000ms)
→ 평균 1000ms, 최소 500ms ~ 최대 1500ms 랜덤 대기
```

### Uniform Random Timer

min ~ max 사이 균등 분포 랜덤 대기

```
Random Delay Maximum: 2000  (최대 2초)
Constant Delay Offset: 500  (최소 500ms)
→ 500ms ~ 2500ms 사이 랜덤 대기
```

## 5. 상관관계(Correlation) 실전 패턴

실무에서 가장 많이 쓰는 패턴입니다. 이 모듈의 CRUD 시나리오에 적용해봅니다.

### 시나리오: 생성 → 조회 → 수정 흐름

```
[1] POST /api/products          ← 상품 생성
      JSON 추출기로 $.id → productId 저장
[2] GET /api/products/${productId}    ← 생성된 상품 조회
[3] PUT /api/products/${productId}    ← 조회한 상품 수정
```

이렇게 구성하면 각 가상 사용자가 자신이 만든 데이터로 테스트합니다.

## 6. JMeter 플러그인

기본 JMeter에 없는 고급 기능을 플러그인으로 추가할 수 있습니다.

### 플러그인 매니저 설치

1. [JMeter Plugins Manager](https://jmeter-plugins.org/install/Install/) 에서 `jmeter-plugins-manager-x.x.jar` 다운로드
2. `apache-jmeter-5.6.3/lib/ext/` 에 복사
3. JMeter 재시작
4. Options → Plugins Manager 메뉴 확인

### 필수 플러그인 목록

| 플러그인 | 용도 |
|---------|------|
| **jpgc - Standard Set** | Response Times Over Time, Transactions per Second 등 고급 리스너 |
| **jpgc - Graphs Generator** | 여러 JTL 파일을 비교 그래프로 시각화 |
| **Throughput Shaping Timer** | 초당 요청 수(RPS)를 정밀하게 제어 |
| **Dummy Sampler** | 테스트 계획 디버깅용 가짜 응답 생성 |
| **Custom Thread Groups** | Stepping Thread Group (단계적 부하 증가) |

### Throughput Shaping Timer 사용법

초당 정확히 100 TPS를 10초 동안 유지하는 테스트:

```
Thread Group 우클릭 → Add → Timer → Throughput Shaping Timer

Start RPS: 100
End RPS:   100
Duration:  10 (seconds)
```

## 7. Non-GUI 모드(CLI) 실행

GUI는 리소스를 많이 사용합니다. 실제 부하 테스트는 CLI로 실행합니다.

```powershell
# 기본 실행
jmeter -n -t test-plan.jmx -l result.jtl

# 옵션 설명
-n          : Non-GUI 모드
-t          : 테스트 계획 파일
-l          : 결과 저장 파일 (.jtl)
-e          : HTML 리포트 생성
-o          : HTML 리포트 출력 디렉토리

# HTML 리포트 포함 실행 (권장)
jmeter -n -t test-plan.jmx -l result.jtl -e -o ./report

# 변수 override (환경별 실행)
jmeter -n -t test-plan.jmx -l result.jtl -Jhost=staging.example.com -Jport=8080
```

> **결과 파일(.jtl)**은 각 요청의 응답시간, 성공여부가 기록된 CSV 파일입니다.
> 이후 GUI에서 열어서 리스너로 분석하거나, HTML 리포트를 생성할 수 있습니다.

### 기존 result.jtl에서 HTML 리포트 생성

```powershell
jmeter -g result.jtl -o ./report
```

## 8. HTML 리포트 분석

`-e -o ./report` 옵션으로 생성된 HTML 리포트는 `report/index.html`을 브라우저로 열어 확인합니다.

### 주요 섹션

| 섹션 | 내용 |
|------|------|
| **Dashboard** | 전체 요약. TPS, 응답시간, 에러율 한눈에 |
| **Response Times Over Time** | 시간대별 응답시간 추이 (성능 저하 감지) |
| **Hits per Second** | 초당 요청 수 (TPS 그래프) |
| **Response Codes per Second** | HTTP 상태코드별 초당 건수 (에러 패턴 분석) |
| **Percentiles Over Time** | 90th/95th/99th Percentile 추이 |
| **Top 5 Errors** | 가장 많이 발생한 에러 상위 5개 |
